# Анализ проекта Gulywood ERP (Campot)

## Как работает приложение
Gulywood ERP — это система управления процессами съемок (ERP), которая объединяет в себе несколько компонентов:
1. **Telegram-бот и Бэкенд**: Бэкенд написан на Python с использованием Flask (`api/index.py`) и Telegram-бота (`pyTelegramBotAPI`). Он работает в Serverless-окружении на платформе Vercel. Бот обрабатывает вебхуки от Telegram, управляет топиками в чатах (создание кастингов, переименование, удаление), принимает отчеты о сменах (`/api/report`) и формирует сообщения с анкетами кастинга.
2. **База данных**: Используется Supabase (PostgreSQL). В ней хранятся данные о проектах (`clients`), команде (`team`), ресурсах (`project_resources`), обратной связи и других сущностях.
3. **Фронтенд**: Набор HTML-страниц (`index.html`, `casting.html`, `timer.html`), которые используются как внутри Telegram (через Web Apps), так и в качестве самостоятельных веб-страниц или мобильного приложения (Cordova/Capacitor). Фронтенд работает с Supabase JS Client для загрузки и отображения данных, позволяет заполнять анкеты на кастинг (`casting.html`) и отслеживать время смен на съемочной площадке (`timer.html`).

## Выявленные ошибки и уязвимости
При анализе кодовой базы были обнаружены следующие ошибки и потенциальные проблемы:

1. **Безопасность**:
   - Вебхук Telegram (`/api` в `api/index.py`) не проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`. Это позволяет злоумышленникам подделывать запросы к боту.
   - Политика CORS настроена слишком мягко (`*`). Для безопасности следует использовать белый список доверенных доменов (`ALLOWED_ORIGINS`).
   - В файлах фронтенда (`index.html`, `timer.html`, `casting.html`) жестко закодирован публичный ключ Supabase (`sb_publishable_...`).
   - В файле GitHub Actions `.github/workflows/deploy.yml` жестко прописан токен Telegram-бота (риск утечки).
2. **Ошибки в логике бэкенда (`api/index.py`)**:
   - Функция `optimize_url` неправильно обрабатывает ссылки Supabase, если в них уже есть query-параметры (знак `?`), так как расширение файла отсекается с помощью `split('.')[-1]` без предварительной очистки от параметров.
   - Эндпоинт `/api/send_excel` не имеет валидации максимального размера данных (например, 15MB) и обработки ошибок `binascii.Error`, что может приводить к ошибкам 500 (Internal Server Error) при отправке поврежденных Base64-строк.
   - Использование глобальной переменной `casting_states` для хранения состояния (при создании кастинга). В Serverless-среде (Vercel) контейнеры часто перезапускаются, и этот in-memory state будет теряться, прерывая диалоги с пользователями.
3. **Проблемы фронтенда и структуры**:
   - Дублирование файлов: Основные файлы (`timer.html`, `index.html`, `casting.html`) существуют как в корне, так и в папке `campot-app/www/`. Из-за этого изменения могут разъезжаться.
   - В `timer.html` используется парсинг дат через `new Date(string)`, что может приводить к ошибкам в Safari. Следует везде использовать функцию-помощник `parseDateSafe`.
   - Ограничения Vercel на размер тела запроса (около 4.5MB) не позволят отправлять тяжелые видеофайлы (50-100MB) через `fetch` из `casting.html`.

## Предложения по улучшению
1. **Перенос состояния в БД**: Замените использование словаря `casting_states` на сохранение временного состояния в базу данных (Supabase) или Redis. Это сделает бота устойчивым к перезапускам сервера на Vercel.
2. **Усиление безопасности**:
   - Реализуйте проверку токена `X-Telegram-Bot-Api-Secret-Token` в роуте `/api`.
   - Передавайте ключи Supabase и токен бота в CI/CD через GitHub Secrets.
   - Настройте строгий CORS.
3. **Оптимизация работы с файлами**:
   - Для загрузки больших видео в `casting.html` настройте загрузку файлов напрямую в Supabase Storage (с использованием подписанных URL) с фронтенда, минуя Vercel-бэкенд. Это обойдет лимит Vercel на размер запроса.
4. **Улучшение качества кода (Code Health)**:
   - Удалите дублирующиеся HTML-файлы или настройте процесс сборки, который будет копировать их из корня в `campot-app/www/` автоматически.
   - Исправьте баг в `optimize_url`, используя модуль `urllib.parse` для извлечения пути до файла перед получением расширения.
   - Внедрите единую обработку дат `parseDateSafe` во всех фронтенд-скриптах.
